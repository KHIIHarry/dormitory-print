## Shared API helpers supplied by Codex

```python
from app.db import get_db, SessionLocal
from app.settings import get_settings
from app.models import *
from app.core import (Actor, DomainError, DTO, Envelope, actor_dep, require_admin,
    require_staff, require_customer, ok, lock, touch, audit, owns_principal,
    authorize_order, seal, unseal, token_hash, enqueue_job)
```

- `DTO` is Pydantic BaseModel with camelCase alias generator, `populate_by_name=True`, `extra='forbid'`. Prefer explicit aliases where frontend differs. `Envelope[T]` is a typed `{data:T,requestId:str}` response. Use `response_model=Envelope[YourDTO]`, and return `ok(data)`; binary routes use FileResponse and authorization.
- `DomainError(code:str,message:str,status:int=422,details:dict|None=None,field_errors:dict|None=None,commit:bool=False)`; handler creates normalized envelope. `commit=True` is only for intentionally persisted mismatch/receipt/exception facts returned with an error.
- `get_db(request)` yields the same SQLAlchemy synchronous Session for the request. Middleware commits once on successful response, rolls back on ordinary errors. **Do not commit or close the request session**. Flush as needed. Worker/CLI obtains SessionLocal separately and owns its transaction.
- `actor_dep(request,db=Depends(get_db))->Actor`. Actor fields: `principal_id,guest_principal_id,account_id,staff_id,staff_role,account_session_id,staff_session_id` (nullable strings), `capabilities:set[str]`, `grant_ids:list[str]`, `restricted:bool`. `actor.id` returns staff_id or principal_id or `'anonymous'`; `actor.role` returns staff_role or CUSTOMER. Staff and customer can coexist; staff paths use staff fields explicitly.
- `require_admin(actor, capability=None)` checks ADMIN, not restricted, capability (`'*'` accepted); `require_staff(actor)` allows ADMIN/COURIER, not restricted; `require_customer(actor,verified=False)` checks principal and optionally active verified account. These are functions called within routes, not dependency factories.
- `owns_principal(db,actor,principal_id)->bool` accepts current guest, own primary principal, or principal linked to active account; not all orders just because a link exists.
- `authorize_order(db,actor,order,scope='ORDER_VIEW')->None` accepts true owner or active grant chain with scope, or ADMIN (route still checks capability); courier access must be separately checked by active assignment in delivery module. Missing access returns404.
- `lock(db,Model,id,expected_version=None)` selects FOR UPDATE,404 if missing,409 VERSION_CONFLICT on mismatch; `touch(entity)` increments version and flags JSON snapshots modified. Never trust client versions without lock.
- `ok(data)->dict` returns envelope; middleware stamps requestId. `audit(db,actor,action,target_type,target_id,reason='',data=None)` appends redacted facts; do not pass passwords, tokens, URLs, contact data or document content.
- `seal(value)->str`, `unseal(ciphertext)->value` protect JSON-compatible data with environment master secret. `token_hash(str)->sha256hex`, raw secrets only on authorized first response/protected same-request replay.
- `enqueue_job(db,kind,target_id,business_key,data=None)->Job` unique persistent job/outbox record. Kind `ASSET`, `PREPARATION`, `EMAIL`, `EXPORT`; worker dispatch calls the module processors below.
- Core middleware handles JSON write Idempotency-Key, canonical body hash, durable encrypted response+Set-Cookie replay atomically with business writes; key mismatch409, replay before version validation. Multipart/raw chunk handlers must call `app.core.idempotent_call(db,actor,request,key,payload,callable)->dict`, where payload contains semantic metadata and content SHA (not multipart boundary). It returns original same-key envelope. It must be called before repeating business creation; filesystem temp cleanup is the module's responsibility.
- Origin/CSRF policy: core sets signed readable `csrfToken` cookie on GET/bootstrap, requires matching X-CSRF-Token and allowed Origin for writes; first `/customer/session` bootstrap may omit CSRF. Test helper `api(client,path,body,method='POST',key=None)` supplies Origin, current CSRF and key.

## Shared snapshot conventions

All JSON mutations: reassign copied dict/list or call touch to flag dirty. Datetimes UTC timezone-aware; business date Asia/Shanghai. Models' `data` holds versioned typed snapshots, not arbitrary client JSON. Every critical owner/state/amount/reference has explicit relational column and relevant check/unique constraint.

Order.data: `quote` full immutable quote view, `history` safe customer timeline, `priority` bool, `locationSnapshot`, `requestedSlotSnapshot`, `confirmedSlotSnapshot`, `settlement` safe summary, and production checklist snapshots. Order.current content uses `content_revision`. Old rows remain, current PrintTask.active true only. Order.actual_started_at is human-recorded physical start; refund_locked is temporary approval lock. Order.status initial PENDING_CONFIRMATION; CANCELED uses contract CANCELLED with close reason in data. Completed refund is separate after-sale state, not fabricated printing state.

Config sections are initialized by root: `prices` (flat keys bwSingle,bwDuplex,colorSingle,colorDuplex,photo,corner,side, nullable integer cents), `services` (serviceEnabled, maxFiles,maxMb,maxPages,maxCopies,maxPixels,maxOrderMb,maxExpandedPages,maxFinalMb,bindingApproved,bindingLimits,formats,photoEnabled,photoCalibrated), `photo` (photoWidthMm,photoHeightMm,margins,a4Margins), `contact`, `announcement` (announcement,serviceEnabled), `workflow` (unpaidTimeoutMinutes,quoteMinutes=15,locationMaxAgeSeconds,locationMaxAccuracyMeters,shortCodeLength,pauses), `retention` (sourceDays7,finalDays30,proofDays30,draftHours24,exportHours24,trashHours24), `map`, `volume-discounts`, `mail`. Root `get_config(db,section)->ConfigSection`, `public_config(db)->dict` flattened frontend Config with versions,features and approved decision capabilities. No real prices/SMTP credentials seeded. Missing prices reject quote, not silently free.

Request sessions never create schema at startup. Alembic and bootstrap CLI perform deployment setup. Core handles generic API envelopes, security headers and idempotency; worker endpoints still enforce object/role/state checks. Tests may directly seed valid shared models and run processors, but production never falls back to test stubs.
