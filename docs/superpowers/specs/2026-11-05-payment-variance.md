# 人工差额收款（用户已批准）

2026-11-05：用户批准“应收保留原报价、实收按到账金额登记、管理员知情接受差额后完成结算”的方案，并要求执行。耗材与利润仅讨论设计，本次不实现。

- 正数应收允许正数多收或少收。金额不同须显式勾选接受差额；收款备注选填。接受后属于最终结算，不生成欠款、自动退款或改价。
- 用户补充：界面只显示“差额：+¥0.50”（绿色）或“差额：-¥0.20”（红色），勾选文案为“接受差额并结算”，不展示冗长的差额解释。
- 零应付继续要求实收为零且人工确认；正数应收不得按零实收免单。
- 前后端共同校验；API 增加 `paymentDifferenceAccepted`（默认 false）。变更金额、选择实收记录、重新打开弹窗均取消差额确认。
- 继续使用整数分、原版本/报价校验、权限、幂等、真实待核对实收复用、容量及配送归集事务。不能重复记款。
- 原报价不变；结算快照、Payment、Receipt 记录真实实收，保存应收、差额、接受事实和备注。审计保存确认人和时间。管理员详情/导出展示差额及备注；客户不获得内部备注。
- 配送根据已确认且内部一致的结算记录判断，不再强制实收等于应收；退款不得超过实收，比例工资按净实收，定额工资不变。
- 测试覆盖多收/少收、未确认拒绝、金额边界、零元、旧记录、实收复用、失败后重试、幂等、配送与账本/退款。PostgreSQL 集成测试必需。

无需新建订单/账本系统或关系表：新增事实使用现有结算及 Payment JSON 快照；历史正常收款无需回填。
