# DormPrint V1 功能定版稿

日期：2026-10-30。

状态：已正式定版。用户已确认Q01—Q36、自定义补充及R01—R06，授权同步文档和实施计划后恢复codex-dsh-desktop开发。功能仍须实现与验收，本稿不代表已上线。

## 1. 需求权威和实施原则

用户本次明确答复优先于旧 01/02/03/04 文档、旧设计文档及前端 demo 的行为。demo 是页面、交互和接口对齐依据，不是自动获批的生产价格、凭据或实机参数来源。

正式方案采用已批准的 FastAPI、PostgreSQL、Redis/Celery、LibreOffice，模块化单体 API 配合独立文件处理和维护任务；React/TypeScript统一应用的三个权限工作区共享同源 `/api/v1`。使用 codex-dsh-desktop 分配边界明确的模块，Codex 负责关键架构、接口整合、代码审查与最终验收。

所有获批功能均须实现前端、接口、持久化、权限及测试，不能用禁用开关、演示数据、空接口或未提供营业参数代替开发。现有界面已覆盖的部分接真实接口；新规则所缺入口、字段、状态及校验一并补齐。

V1 在代码、数据库、文件处理、接口与真实设备/生产环境不同层面分别验收；未提供服务器、SMTP和打印机等事实配置时，交付相关配置机制和部署包，不虚报已部署或实机通过。

## 4. 已批准基础闭环及约束

1. 上传/分片恢复→真实转换→文档分段或照片布局→服务端最终PDF→逐任务预览确认→报价→订单→人工线下正数收款或零元结算→实际开印登记/尝试与结果→装订→人工装袋→批次开始→配送凭证→售后/退款。
2. 一单多文件，每文件多任务；单面n×份数用纸，双面ceil(n/2)×份数用纸，各任务各份独立补奇数背面。份数已在最终PDF展开，打印机设1份；不跨任务共纸。
3. 最终PDF不可变，ID/hash/内容版本逐项匹配，客户确认件与管理员下载件一致；客户端页数、金额和按钮状态不作权威。只看预览不自动确认，加载/身份/版本失效不得确认。
4. 图片逐张选择A4或照片；A4图片作为DOCUMENT走相同标准化，不把客户端生成PDF视作可信最终件。HEIC的真实解码和前端入口按Q12新增。
5. 订单备注选填，trim后最多30字，与内部备注、收款说明分离。
6. 配送免费、强制人工装袋；客户不定位、不填楼层房间；真实交付照片或明确免拍原因，定位或已批准例外，服务端交付时间。地图热点不冒充GPS。
7. 游客/客户/员工/订单链接身份隔离；显式游客关联与撤销旧游客凭据、单单导入继承源权限/到期/撤销；对象级授权与当前来源并集；手机号/短码不是访问凭据。
8. 新人券、受邀新人券和邀请奖励可配置；可同时持多券但订单最多一券，与满量优惠自动择优且不叠加，同额优先满量；满量仅本单A4实际用纸及A4打印小计，游客同享。
9. 预算、券发放/预约/核销/释放、补偿券和奖励纠错持久化且业务唯一；退款事件不得改写既有报价、旧核销或另一单实付。补偿券预算/资金来源须独立可追踪，不擅自占用已停止活动的新发行额度。
10. SMTP真连接/可靠发送队列、7类中文模板编辑/预览/安全测试/恢复默认；运营通知默认关闭、明确订阅；入队和SMTP受理不冒称已送达。一次性秘密和验证动作不得由邮件GET预取直接消费。
11. 配置强类型、白名单、版本及审计；状态改变以明确动作和守卫执行，不接受万能status覆盖。数据库事务/锁/唯一约束覆盖订单、优惠、收退款、容量、生产、批次、交付、删除恢复与幂等。
12. 未知提交/上传结果须有按当前主体操作标识的查询与原请求安全重放闭环；私有API/文件不缓存，PWA只缓存静态壳。导出、文件状态及取消不得假百分比/假完成。

## 6. 现有前端对齐范围与缺口

已读配置入口：`src/admin/operations.tsx` 的价格、服务与限制、照片校准、微信联系、公告营业、决策；`src/admin/logistics.tsx` 的时段和批次；`src/admin/growth/volume.tsx` 的满量；`src/admin/growth/promotions.tsx` 的活动；`src/admin/growth/mail.tsx` 的SMTP和模板。

这些入口复用，但当前不是全量新规则的成品界面：

- 配置保存仍有`expectedVersion:1`和全配置提交，需改为真实section DTO/版本，不让后台越权修改其他section。
- 装订仍显示D-04未定版而禁用，保留策略仍为待定占位；须按本次决定更新文案、字段和服务端守卫。
- Excel分页/区域、HEIC、分片恢复、服务端草稿、作业取消、实际开印、售后申请/代办、自定义退款依据、补偿券、定位审批、细分权限、个人导出/注销、订单/收退款导出及四类暂停都需检查并补齐完整前端入口。
- 时段需区分requestedSlot与confirmedSlot及未保证名额状态；容量在人工结算事务占用。
- 配送需真实assignment ID，不能继续把batch ID当交付执行ID；配送员start有独立受限权限。
- OpenAPI需补上传、分片、恢复、售后/退款、补打、装袋、批次、审批、注销、导出等明确DTO与运营响应；与生成器和客户端同步，不接受generic object代替接口定版。
- demo示例价目、10文件/50MB、示例时段容量、127×89mm等只是现有实现值的来源；生产配置是否采用其数值须显式保存和校验，不自动带入假订单、假联系方式或默认密码。
