## 2. 设计目标与决策规则

统一原则：窗口出现用过渡，任务等待用加载，操作结果用状态变化。

每个交互先回答四个问题：用户触发了什么、系统正在做什么、当前哪些操作可用、结束后如何确认结果。

按以下顺序选择反馈：

1. 数据已就绪或本地内容可立即呈现：直接展示；需要表达出现、消失或空间关系时加短过渡。
2. 首次请求结构已知的内容：使用对应区域的骨架屏。
3. 用户触发的短时局部操作：使用按钮或区域内加载圈和具体文案。
4. 持续任务且完成量可测：使用确定进度条或进度环。
5. 持续任务但完成量不可测：使用不确定进度条和可证实的阶段文案。
6. 等待用户选择、人工处理或线下履约：使用静态状态、操作入口或时间线，停止加载动画。

同一任务只保留一个主要等待指示。同一页面不同独立任务可以分别反馈，但不得出现整页转圈、局部骨架、文件进度同时重复解释同一请求。

## 3. 状态模型与不可违反的约束

### 3.1 内容资源

区分以下状态，不得只用一个全局 loading 布尔值支配全部页面：

- 初次加载：当前资源没有可用数据，显示匹配结构的骨架。
- 已就绪：成功获得当前资源数据，正常展示。
- 空数据：请求成功且结果为空，显示对应空状态。
- 刷新中：已有可用数据，保留内容并显示轻量更新提示。
- 初次加载失败：对应区域错误与重试，不误报空状态。
- 刷新失败：在资源身份及权限仍有效时保留旧内容，标明更新失败与重试。

“可用数据”必须属于当前身份、权限、订单和查询条件。切换筛选条件时可临时保留同权限下的旧结果，但必须清楚标记“正在更新，当前为上一筛选结果”，并禁用依赖新结果的操作；若会造成歧义，改用结果区域骨架。不得在新筛选标题下无标识地显示旧结果。

退出登录、切换账号、权限撤销或访问范围改变时，立即清理旧身份内容和对应缓存，不得为了淡出而继续展示旧用户数据。静态公共页面不受无关业务请求失败牵连。

### 3.2 文件与后台任务

按实际能力映射：等待开始 → 本地读取（如需要）→ 上传 → 已上传、等待处理 → 处理中 → 就绪；任意活动阶段均可能失败。等待开始的文件可直接移除。真正支持取消的活动任务才允许进入“已取消”。

- “上传字节达到 100%”只表示传输进度达到终点，不代表服务端已接收、转换成功或可打印。
- 字节传输完成而响应未返回时，显示“上传已完成，正在确认”，进入下一阶段后改用该阶段指示。
- 只有服务端或对应本地处理流程明确确认就绪，才显示“已就绪”。
- 已上传但排队、转换期间，不能停留在一个看似全部完成的 100% 条上。
- 读取、上传、处理、就绪必须使用符合文件类型的名称；普通图片和 PDF 不应全部标为“转换中”。
- 就绪后仍待选纸张、待确认输出等属于用户操作状态，不再转圈。
- 若后端只有 PROCESSING，就只展示“处理中”或可确认的任务类型；不得推演出不存在的细分阶段。
- 网络恢复、重新进入页面或重试时，先获取实际任务状态；没有持久化及恢复能力就不能承诺刷新后继续。

进度值只在相同任务、相同阶段、相同总量口径内比较。更换阶段、重试或任务版本改变可以重新起算，必须同步更新阶段文案；不要表现为同一进度无故倒退。

### 3.3 业务提交

区分未提交、提交中、明确成功、明确失败、结果待核实。

下单、收款、发布批次、交付确认等操作在请求发出后发生超时或断网，可能已经落库。此时显示“提交结果待核实”，优先查询结果或用既有幂等机制恢复，不直接宣称失败，不引导创建重复业务操作。收到明确业务拒绝时才显示具体失败原因。

按钮锁定必须从操作开始立即生效，不能等加载动画出现才防重复。

## 4. 视觉组件规范

### 4.1 骨架屏

- 仅用于尚未到达的内容；标题、导航、已知文件名、上传入口和本地表单直接显示。
- 形状匹配真实布局：列表卡、表格行、详情摘要、时间线、统计卡、资料卡和预览纸张，不使用一套通用灰块应付全部页面。
- 暖灰、低对比，圆角与所在组件一致。默认轻微明暗变化，禁止大面积强亮扫光。
- 占位高度、列宽、图片比例尽量接近真实内容，加载后不明显跳动。移动端按卡片布局，桌面按对应表格或多栏布局。
- 骨架元素本身不进入焦点序列，不逐个向读屏器播报；容器给出一次有意义的加载状态。
- 数据到达后原位替换，最多一次短淡入，不让骨架退场与真实内容入场串行占用额外时间。
- 不给按钮、整个弹窗外壳、提示消息或已完成的内容套骨架。

### 4.2 加载圈

- 按钮内建议 16–18px，局部区域约 24px。优先使用现有图标和主色，正文按钮内使用足够对比的颜色。
- 配具体文案，如“正在保存”“正在获取位置”“正在读取图片”，不用全站统一“加载中”。
- 按钮保持宽高和对齐稳定，加载图标替换原图标，不叠加两个意义相同的图标。
- 单个任务不重复显示按钮圈、卡片大圈和全屏圈。
- 只有没有可合理占位的初始化等特殊场景，才考虑页面级等待；常规数据页面使用局部或结构骨架。

### 4.3 进度条与图片进度环

- 文件行进度条建议 4px，独立任务区域建议 6px，图片缩略图上的进度环约 32px；根据触控与文本布局适配。
- 确定进度来自真实字节或明确完成量，数值限制在合法范围。总量未知、缺失或为零时进入不确定模式，不除零，不显示 NaN 或假百分比。
- 上传百分比按传输适配实际可测的请求体口径计算；若包含 multipart 开销，不虚构“文件字节已传输量”。阶段和口径应一致。
- 传输进度环表示已完成弧段，不应像不确定加载圈一样整环旋转。
- 不确定进度条不显示百分比，配可确认的任务名称或阶段。
- 每个文件独立显示进度。多文件顶部用“已就绪 3/5 个”等准确汇总，区分就绪、失败、等待和待选纸张，禁止混合上传与转换耗时计算虚假总百分比。
- 进度达到终点后，按任务状态替换为确认中、处理中、成功或失败；不要把绿色完成态用于尚未确认成功的阶段。

### 4.4 成功、错误与静态业务状态

- 成功用文字、图标和必要的状态变化确认；不要只靠圈消失或颜色变化表达。
- 错误就近显示具体原因与可执行动作，保留用户输入和已完成文件。输入校验错误不使用屏幕晃动、表单抖动或闪红。
- Toast 只承载简短辅助反馈；必须阅读的错误、结果待核实和操作阻断原因放在页面内持续展示。
- 多个文件失败以文件内原因加一次汇总提示呈现，不连续轰炸 Toast。
- “待打印、待装袋、配送中、待付款、待人工确认”等用静态标签和时间线，不持续转圈。

## 5. 动效时序与视觉语言

建立共享动效变量，不在各页面随意填写时长。以下为本项目的参数，不是强制行业阈值；弹窗与上传入口沿用已验收的现有规格：

| 动效用途 | 建议时长 | 规则 |
|---|---:|---|
| 按下、选中、边框或颜色反馈 | 80–120ms | 立即响应，避免夸张缩放 |
| 菜单、提示、局部状态淡入 | 120–160ms | 短、轻，不影响目标定位 |
| 普通弹窗进入 | 窗口 320ms；遮罩 300ms | 同步开始淡入；窗口 ease-in-out，遮罩 linear；窗口内内容同时呈现 |
| 普通弹窗退出 | 窗口、遮罩均 180ms | 沿用 ease-out；比进入快，不保留可操作残影 |
| 侧栏、底部抽屉、折叠区域 | 200–240ms | 用位移或展开表达真实空间关系 |
| 页面内容切换 | 120–180ms | 按需使用，导航框架固定 |

普通弹窗沿用上表已验收的淡入、淡出曲线；其他进入默认平缓减速，可沿用 cubic-bezier(0.16, 1, 0.3, 1)，其他退出用简单加速或 ease-in。进度反馈可以平滑追随真实数据，但不得提前于数据抵达终点。

禁止默认加入回弹、弹簧、全页缩放、逐字显示、滚动揭幕、卡片集体飞入、金额滚动计数和无业务含义的循环装饰。价格、页码、提取码、电话和核对结果应直接可读。

同一触发中的遮罩和窗口同步开始过渡，普通弹窗分别按上表时长结束；退出时二者同步结束后再移除容器并释放滚动锁。表单字段、标题和按钮不分批排队入场。不同独立区域随数据就绪分别出现，不能故意等全页齐备。

## 6. 窗口、抽屉与展开区域的完整生命周期

### 6.1 普通弹窗

纸张选择、确认删除、二维码查看、例外说明等内容已经在本地的窗口：直接打开并淡入，不添加虚假加载。

支持打开、进入中、已打开、退出中、已移除这些表现状态；可以简化内部实现，但必须保证：

1. 打开后正确设置对话框语义，焦点进入窗口并保持可见，背景不可交互；保留 Esc、遮罩关闭等原有行为及原有关闭限制。
2. 进入与退出期间正确锁定滚动，不因滚动条消失而横向跳动；已有滚动条补偿能力优先复用。
3. 用户请求关闭后立即使窗口内容不可操作，退场期间遮罩继续防止点击穿透，退出结束才解除锁定并移除容器。
4. 隐藏或关闭内容不能仍被 Tab 访问。过渡状态不应冒充真实异步任务，aria-busy 仅用于内容实际繁忙的情形。
5. 关闭后焦点返回原触发元素；若原元素已移除，返回最近合理位置，不能落到无意义或隐藏节点。
6. 支持“打开后立即关闭”“退出时重新打开”“快速连续开关”。取消旧定时器或旧动画回调，不能误卸载重新打开的窗口。
7. 不单纯依赖 animationend：减少动画、系统动态切换设置、节点变化等情况下也要可靠清理，保证不会残留遮罩或滚动锁。
8. 存在多层窗口时按栈管理焦点、Esc、遮罩和滚动锁；若项目可以改成单窗口内切换，应优先避免无必要叠层。不能内层关闭后解锁仍打开的外层。
9. 本地关闭与业务取消分开处理。关闭视图不代表后端任务已取消；有未保存内容或正在提交时沿用准确的业务提示。

### 6.2 抽屉、下拉与折叠

- 侧栏从对应边缘滑入，底部抽屉从底部出现，遮罩同步变化；不改变既有容器形态来追求动画。
- 下拉菜单紧邻触发点短淡入，不进行大幅位移；触屏不依赖 hover。
- 折叠内容与箭头由同一展开状态驱动，收起即移出可操作序列，不留隐藏链接。
- 默认只让一个层级承担主要运动，不在展开内容内再逐行入场。
- 控制展开动画的内容范围，避免重新排版整个页面。必要高度变化可以使用有边界的 grid 或尺寸过渡，但应实际验证布局性能。

## 7. 页面切换与刷新策略

1. 页头、侧栏、底部导航等外壳稳定保留，只切换对应内容区；路由本身不制造假进度条。
2. 已有当前资源有效数据时直接展示，后台刷新只显示轻量提示，不退回骨架，不清空表单。
3. 首次进入且数据未到达时，使用页面对应骨架。缓存命中或响应很快时直接显示，不强制播放完整骨架动画。
4. 页面过渡默认直接切换或短淡入；只有真实前进后退关系明确时才使用方向性过渡，禁止所有路由统一横滑。
5. 不让旧页面和新页面长时间半透明叠加，尤其不能叠加不同订单或不同账号的信息。
6. 页面状态更新不重复触发整页入场；筛选、输入、报价、轮询更新仅改变相关区域。
7. 新页面合理处理标题焦点与滚动位置；返回列表尽量恢复位置，刷新不抢焦点，表单错误定位到实际错误。
8. 慢请求可以触发骨架或任务反馈，但页面过渡结束不代表请求结束，两者分别由各自状态驱动。

## 8. 用户端逐场景要求

路由按当前配置与 docs/PAGES.md 核对，以下是场景清单，不允许仅修改共享 Loading 后宣称完成覆盖。

| 页面／场景 | 首次加载 | 操作、刷新与结果 |
|---|---|---|
| 首页 /u/ | 品牌与本地服务内容直接显示，公告、真实价格等动态区局部占位 | 首页图片预留比例，加载后不顶动布局；动态区失败局部重试 |
| 上传 /u/new | 上传入口和步骤直接显示，依赖配置缺失时局部占位并明确限制 | 文件立即入列，按读取、上传、处理、就绪独立反馈 |
| 图片纸张选择 | 本地弹窗直接淡入 | 待选纸张停止加载；A4 生成期间仅相关操作繁忙，错误保留原图与选择入口 |
| 打印设置 /u/new/settings | 已有草稿直接呈现，预览独立等待 | 选项即刻选中；预览重算局部反馈，不清空设置 |
| 照片编辑 /u/new/photo/:id | 图片按真实比例占位 | 拖动、缩放、旋转立即响应，不每帧转圈；耗时输出才局部等待 |
| 确认订单 /u/review | 已知文件名、步骤、联系信息表单保留；最终文件和价格分别等待 | 生成最终文件、渲染预览、报价、提交独立反馈，准确控制确认与提交条件 |
| 成功／联系页 | 请求未确认成功前不预显成功内容 | 订单状态刷新局部处理；二维码加载失败给准确提示 |
| 订单列表 | 订单卡骨架，保留搜索筛选框架 | 区分首次、刷新、分页、无结果；列表操作就近反馈 |
| 订单详情 | 摘要、时间线、文件区域骨架 | 局部修订与刷新，业务状态使用标签，不转圈等待配送 |
| 登录、注册、验证、找回、重置 | 本地表单直接显示，必要身份检查单独处理 | 提交按钮繁忙，服务端错误就近展示；邮件受理不等同已送达 |
| 账号、会话、优惠券、邀请 | 资料卡、列表或券卡骨架 | 保存、撤销会话、兑换等操作局部反馈；身份变化清理旧数据 |
| 订单链接兑换 | 已知说明与表单直接展示 | 兑换中按钮反馈，成功取得访问权后再进入内容；不显示无权订单占位数据 |
| 帮助 | 静态规则直接显示，动态价格单独加载 | 公共帮助不被无关订单接口失败整页阻断 |

### 8.1 上传细则

- 文件选中后先完成类型、大小等必要校验，合法项立即出现在队列；多文件尚未开始的项显示“等待上传”。本地格式校验不能伪装成上传中。
- 图片可尽早显示本地缩略图并叠加进度环；文档保留文件图标，在文件名下方显示进度条。已知文件名和大小不替换为骨架。
- 上传 transport 若采用 XMLHttpRequest 或其他支持进度的适配，必须保持原有同源凭据、CSRF、幂等键、错误解包、取消、身份代际校验等语义；不为进度绕开统一安全与业务机制。
- 若暂时无法可靠获得传输进度，使用不确定指示。演示模式不得用计时器伪装真实网络百分比。
- 一个文件失败不阻塞其他文件。重试根据失败阶段决定重新上传还是重试处理；没有 assetId 的上传失败项不能调用转换重试接口。
- 删除活动上传项必须中止对应传输或阻止其后续状态写入；删除服务端处理项不等于已取消服务端处理，准确处理资源与界面语义。
- 文件移除、重试、身份变化、组件卸载后，旧上传回调、旧轮询和旧图片解码结果不能重新插回队列或覆盖新任务。
- 批量汇总分清“可打印就绪”和“待选纸张”。进入下一步仍遵守全部有效文件与设置的业务条件。

### 8.2 转换、生成与预览细则

- Word／PPT 默认“正在转换为 PDF”配不确定进度条。只有明确字段支持时才展示排队、转换、解析页数等细分阶段。
- 最终 PDF 生成默认阶段式任务区；有真实完成回调才能显示“已生成 2/4 项”，此处是任务数，不冒充时间百分比。
- 当前系统不支持某后端阶段时，不增加假的阶段推进；明确记录待后端提供的数据能力。
- 预览首次载入保留纸张比例和工具栏，加载状态只覆盖画布区域。
- 翻页保留稳定容器。若临时保留旧画面，明确标记正在切换，显示页与目标页语义清晰；新画面渲染完成后再允许针对该页的确认，不让旧画面配上新页码误导核对。
- 快速翻页、切换文件、缩放、关闭预览时，中止或淘汰旧渲染任务，旧 canvas 结果不能覆盖最新页。
- 报价未返回显示“正在获取价格”或“—”，禁止先显示 ¥0。重新报价期间旧金额如保留，标明尚未更新且不能作为当前确认价格。
- PDF 未完成、报价失效或重新生成时，按既有版本和内容规则管理确认记录。动画不能替代或放宽提交条件。

## 9. 管理端逐场景要求

| 场景 | 反馈要求 |
|---|---|
| 工作台总览 | 统计卡、待办、批次等独立骨架与独立到达，不被一个慢区块拖住全页 |
| 订单、客户、审计、异常、回收站、营销记录 | 保留表头和筛选；首次行骨架，刷新局部提示；分页与查询遵守当前结果标识规则 |
| 订单与客户详情 | 摘要、文件、日志等分区占位；行内操作只影响相关对象 |
| 打印工作台与最终 PDF | 预览局部加载；调用系统打印不等于出纸成功；实际打印结果仍需人工确认 |
| 装订、装袋、交付、收款核对 | 操作按钮立即反馈，核对清单与提取码稳定；接口确认前不推进业务完成态 |
| 批次影响预览、发布、开始、改期 | 影响计算与最终提交分开显示；结果版本变化后重新核对，不用动画掩盖条件变化 |
| 时段、地图、配置、员工与账号 | 本地表单直接展示，数据区按需占位；保存和测试分别反馈，不全屏锁住无关操作 |
| 底图、二维码、配置图片上传 | 图片局部进度；替换成功前保留旧有效图，失败不清空现有配置 |
| SMTP 连接、测试邮件、邮件模板 | 连接、申请发送、模板保存分别反馈；服务受理不宣称邮件已送达 |
| 营销导出 | 显示真实作业状态：受理、排队（如有）、生成、可下载或失败；未知进度不用百分比，提交导出不等于文件已生成 |

后台以高频核对为优先，弱化页面入场，不给提取码、金额、打印页数添加数字动画。抽屉与导航沿用稳定位置和清晰选中态。

## 10. 配送端逐场景要求

- 批次首页、楼栋分组、订单详情：对应任务卡骨架；数据到达后提取码、楼栋、联系方式直接可读。
- 获取设备定位：按钮小圈配“正在获取位置”；权限等待、拒绝、不支持与超时准确区分。调用浏览器权限后停止重复触发；不显示虚假定位百分比。
- 拍照与照片读取：本地照片区域反馈，不阻塞可独立查看的信息；交付照片上传使用缩略图进度环。
- 照片失败保留其他表单与已取得的合法定位；定位失败不清空有效照片。位置有效性及业务例外仍依现有规则核验。
- 提交交付与异常：按钮繁忙，防重复；明确成功响应后才显示交付成功。超时进入结果待核实。
- 电话、地址和核对信息不使用延迟显现；照片、定位、提交不重复叠加全屏加载。
- 移动端考虑安全区、键盘弹出、弱网、单手操作和从相机返回，不使反馈遮住主操作或错误。

## 11. 等待时长、失败与取消

1. 操作后立即更新可用性与必要状态文字；一般操作的加载动画可延迟约 200ms 再出现，减少快速请求的闪烁。上传入口沿用现有规格：立即锁定重复选择，保持“选择文件”的文案、宽高和明暗稳定，不替换成繁忙按钮；仅在任务持续超过 350ms 时于原说明文字位置显示辅助处理提示，已入列文件仍按实际阶段独立反馈。完成早于对应延迟阈值时取消待出现的提示或动画；延迟不得推迟真实任务、纸张选择或操作结果。
2. 不为凑最短展示时间阻挡已就绪内容或拖延操作结果。动画退场只负责视图清理，不延后真实业务状态。
3. 等待约 10 秒仍无结果时增加“耗时比平常稍长”等说明，展示可用的查看、返回或重试入口。具体超时依据操作类型与契约，不使用统一固定秒数把所有长任务判失败。
4. 进度暂时不变不能自动等同失败；持续轮询成功但任务仍处理与轮询请求失败是不同状态。
5. 轮询不得重叠失控，按真实能力使用退避；页面隐藏时暂停或降频，返回后核实最新状态；已完成、失败、取消、权限失效后停止。
6. 离线时退出普通等待，显示网络状态。已取得且仍有权访问的内容可保留，业务提交按产品现有规则禁用；不能承诺不支持的自动重传或断点续传。
7. 401、403、资源过期、409 版本冲突、文件格式或大小错误，应显示对应原因与恢复路径，不能全部转换成“加载失败”。
8. 仅实际支持的任务提供取消。取消本地请求不等于撤销服务端提交；取消结果未知时继续核实，禁止给出虚假的“已取消”。
9. 本地文件、生成文件和设置目前不支持刷新恢复时，离开提示应说明实际影响，不因新增动画改变既有数据生命周期。

## 12. 无障碍与低性能环境

- 所有非必要空间运动和循环装饰尊重 prefers-reduced-motion，减少动态效果下采用即时切换、极短淡入或静态文本反馈。
- 加载圈停转后仍需保留“正在处理”等文字，不能仅关闭动画使等待语义消失。确定进度数值继续准确更新。
- 使用原生 progress 或正确的 progressbar 语义；确定进度提供合法范围与当前值，未知进度省略当前值，不能把未知表示成 0%。
- 加载区域合理使用 aria-busy，重要状态用适度的 live region；阶段变化与错误可播报，不逐字节、逐帧或每百分之一打断读屏。
- 键盘焦点、对话框语义、Esc、焦点归还与隐藏元素不可交互均须保持。减少动画模式同样需要正常卸载和解锁。
- 动态偏好在窗口打开时发生变化也必须正确完成清理。
- 优先对局部 opacity、transform 做过渡。不要全局 transition: all，不持续动画大面积阴影、模糊或背景滤镜，不永久滥用 will-change。
- 高频进度更新与预览绘制合理节流，不能使整个应用逐帧重渲染；终态要立即落定，不能被节流遗漏。

## 13. 实现组织与能力边界

先盘点公共组件及全部异步入口，输出页面与状态覆盖表，再实施。

按职责复用：加载圈、确定／不确定进度、图片进度环、按钮繁忙反馈、骨架基础块、页面级骨架组合、局部资源状态、窗口生命周期及共享动效变量。命名适配现有项目，不强行建立包含所有业务的大组件。

状态、视觉和传输分层：

- 业务状态决定“当前真实发生了什么”。
- 视觉组件决定“用什么形态表达”。
- 动效生命周期决定“如何进入、退出与中断”。
- 传输与任务适配提供真实进度、取消能力和版本信息。

请求与回调至少具备任务或资源标识、请求序号及身份代际校验，按需要带版本；卸载、重新选择、删除、重试后，过期结果不能写回。

若后端未提供精确转换进度、阶段、取消、导出查询等信息，前端采用本规范定义的诚实退化方案，并单列契约缺口。只有经契约认可的字段才能对外请求或依赖；不要擅自假定新增接口可用。

必要的后端协作信息可包括任务标识、真实状态与阶段、可选完成量与总量、可恢复错误、取消能力、更新时间及任务版本。缺失完成量时使用不确定模式，缺失阶段时使用统一处理中，缺失取消能力时不显示虚假取消入口。

## 14. 验证与验收矩阵

针对异步状态、并发、焦点与业务提交补充有意义的自动化测试；简单时长常量和可逆样式不必编写只复述实现的测试。运行项目规定的相关测试与构建，并对桌面、移动和减少动画模式做实际浏览器验证。

必须验证以下场景：

1. 快速请求：无不必要的圈或骨架闪现，重复提交仍被阻止。
2. 慢速初次加载：结构骨架正确，外壳稳定，完成后不跳动。
3. 缓存命中和后台刷新：内容不清空，不重复整页入场。
4. 成功空数据、初次失败、刷新失败：三者展示不同且恢复路径正确。
5. 筛选或分页竞态：旧响应不覆盖新结果，旧结果不会伪装成新筛选结果。
6. 混合多文件上传：排队、读取、上传、处理、失败、就绪、待选纸张独立准确，汇总一致。
7. 真实可测上传与未知总量上传：分别使用确定和不确定反馈；传输 100% 后响应或处理未完成不误报成功。
8. 部分文件失败：其他文件继续，重试命中正确阶段与接口。
9. 上传中删除、取消、重试、退出、切换账号：旧回调不复活文件，不泄漏旧内容。
10. 后端只有 PROCESSING：没有虚构阶段、百分比或剩余时间。
11. A4 图片生成和纸张切换：操作繁忙、错误保留、确认条件与原图生命周期正确。
12. 最终 PDF 生成、报价与预览独立等待：页面可继续合理填写，未就绪不能确认或提交。
13. 快速 PDF 翻页和换文件：画面、页码、加载文案一致，旧渲染不覆盖新结果。
14. 下单、收款、交付的超时和断网：结果待核实，不重复创建业务操作。
15. 弹窗快速开关和关闭后立即重开：无残留遮罩、滚动锁、点击穿透或错误卸载。
16. 对话框、抽屉、折叠和下拉的键盘操作：隐藏内容不获焦，关闭焦点归还合理。
17. 页面滚动条存在与不存在时开关窗口：布局不横跳，页面位置正确保留。
18. 多层窗口如存在：内层关闭不破坏外层焦点与滚动锁。
19. 减少动画初始开启及过程中切换：仍能正确关闭、解锁、显示任务状态。
20. 弱网和离线恢复：原输入保留，任务实际状态重新核实，无无限 Toast 或失控轮询。
21. 管理高频核对：提取码、金额与页数即时可读；打印尝试不自动显示打印成功。
22. 配送定位拒绝、超时、照片失败和返回相机：分别恢复，信息不无故清空。
23. 后台导出、SMTP 测试：受理、生成、可下载、投递结果依真实能力区分。
24. 三端路由全覆盖：每个现有页面或路由类别都标记适用方案、已有能力、实现位置和验证结果，无遗漏的通用“正在加载”。

验收以真实可观察结果为依据。截图验证结构、状态与视觉稳定；短录屏或可重复操作验证进入退出、快速中断与连续状态，不能只用静态截图证明动效正确。

## 15. 执行顺序与最终交付

按以下顺序推进，每步保留可运行状态：

1. 盘点页面、公共组件、异步入口、状态来源和契约能力，建立覆盖表，确认可复用的已有实现。
2. 建立共享动效变量、按钮繁忙反馈和窗口生命周期，统一现有弹窗、抽屉、菜单、折叠。
3. 区分首次加载、刷新、空数据和错误，完成三端对应骨架与页面切换策略。
4. 完善用户上传、真实传输进度、文件处理、最终 PDF、预览和报价的独立状态；后端缺失部分按明确退化方案呈现。
5. 覆盖后台生产、配置、导出以及配送定位、照片、交付；核实高风险操作的结果待确认与幂等恢复。
6. 完成相关测试、构建、浏览器验收和必要修复，整理交付证据。

最终交付包括：

- 实际可运行的代码改动及相关测试。
- 一份项目内的加载与动效规范文档，记录共享参数、状态语义和组件用法。
- 一份三端页面／交互覆盖表，逐项写明方案和实际完成情况。
- 一份验收记录，包含执行过的命令与结果、桌面和移动端证据、减少动画与关键异常路径结果。
- 一份剩余后端契约缺口及当前降级行为说明，仅列真实缺口。

完成报告明确区分“已实现且验证”“已实现但环境无法验证”“需后端配合”。不能以设计文档代替代码落地，也不能把演示或 mock 验证写成真实后端联调通过。
