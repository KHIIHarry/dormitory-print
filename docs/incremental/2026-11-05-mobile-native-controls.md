# 移动端月份控件与布局修复

用户提供的 iPhone 截图显示收支页横向溢出、工资月份框越过卡片内边距。此轮不改账目计算、接口或数据库。

- 将 month 纳入共享 iOS 原生日期控件保护，明确 border-box、物理/逻辑宽度与 appearance，约束 WebKit 内部日期文字区域。
- 收支工具栏拆分操作组与月份筛选；手机月份独占一行，桌面保持对齐，键盘顺序与视觉分组一致。
- 工资容器和自适应网格允许收缩；同类修复覆盖个人工资、管理工资和人工工资条目弹窗。
- 为单行 select 显式设置44px高度，修复 WebKit 原生下拉框忽略 min-height、实际仅22px的行为，不影响 multiple/size 列表。
- 新增移动 UI 配置和 npm 命令；将规则写入 DESIGN.md、docs/UIUX-移动端布局规范.md、src/AGENTS.md，约束后续开发。

验证：381项单测与生产构建通过；原有收款和配送界面18项浏览器回归通过；新增Chromium/WebKit布局12项回归通过，覆盖320/375/390/430/768/1440px、月份切换与弹窗。低优先级原生最小宽度压力测试在旧代码下观察到6项失败，修复后通过。额外用真实FastAPI/PostgreSQL/Vite分别跑Chromium和WebKit的收支/个人工资流程，核对金额、采购、作废、分页、离线保留输入、触控和卡片边界。

测试中的接口夹具仅用于独立布局检查；真实后端用独立测试schema，测试后清理。WebKit离线探测会产生预期的网络诊断，脚本只在故意离线阶段排除该类诊断，其他JavaScript异常仍导致失败。

限制：桌面WebKit和触控模拟不等于真实iPhone UIKit，本轮不宣称真机验收。用户截图保留为原问题证据。截图位于本地 test-results/ 与 output/finance-qa/{chromium,webkit}/，不纳入Git。

发布：仅需按既有流程重新构建、发布前端；没有新增数据库迁移。
